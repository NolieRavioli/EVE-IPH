# EVE Isk per Hour (EVE-IPH)

A Windows desktop tool for [EVE Online](https://www.eveonline.com/) industrialists. Calculates ISK-per-hour profitability for manufacturing, invention, reactions, mining, and PI using the EVE Static Data Export (SDE) and live data from CCP's ESI API.

VB.NET / WinForms / .NET Framework 4.7.2, backed by SQLite via `System.Data.SQLite`.

## Requirements

- Windows 10 or later
- [.NET Framework 4.7.2+](https://dotnet.microsoft.com/download/dotnet-framework)
- Visual Studio 2019+ with the **Visual Basic** workload (only for building from source)
- An `EVEIPH DB.sqlite` file next to `EVE Isk per Hour.exe`

## Database

The app expects a SQLite file named **`EVEIPH DB.sqlite`** in the working directory (filename is hard-coded in [Globals.vb](Globals.vb#L57)). It must contain both the SDE tables and EVE-IPH's own `ESI_*` tables. If it doesn't, the app crashes at startup with:

```
System.Data.SQLite.SQLiteException: SQL logic error
no such table: ESI_STATUS_ITEMS
```

The `ESI_*` tables are not generated by any code in this repo — they live in a prebuilt template DB published by the project maintainer.

### Download the prebuilt DB (recommended)

```powershell
cd "<folder containing EVE Isk per Hour.exe>"
Invoke-WebRequest `
  -Uri "https://raw.githubusercontent.com/EVEIPH/LatestFiles/master/EVEIPH%20DB.sqlite" `
  -OutFile "EVEIPH DB.sqlite"
```

### Refresh the SDE (advanced)

When CCP ships a new SDE and the prebuilt DB is stale:

1. Start from a working prebuilt `EVEIPH DB.sqlite` (above) — its `ESI_*` tables are required.
2. Use [EVE-SDE-Database-Builder](https://github.com/NolieRavioli/EVE-SDE-Database-Builder) to produce a fresh SDE-only `EVEIPH DB.sqlite` (Database Type: SQLite, Check All, Build Database) into a separate folder.
3. Run the **EVEIPH Updater** project (`EVE-IPH-Update-Program\`) to merge the `ESI_*` and user tables from the old DB into the new SDE DB.

## Build from source

1. Open [EVE Isk per Hour.sln](EVE%20Isk%20per%20Hour.sln) in Visual Studio.
2. Restore NuGet packages (already vendored under `packages\`).
3. Build the `EVE Isk per Hour` project.
4. Place `EVEIPH DB.sqlite` in the build output folder (`bin\Debug\` or `bin\Release\`).
5. Run.

## ESI registration

Character-linked features (skills, blueprints, assets, industry jobs, standings, market orders) require an ESI app registered at <https://developers.eveonline.com/>. Enter the resulting **Client ID** and **Secret Key** in the in-app ESI settings dialog. Manufacturing math and pricing work without ESI; only character import is gated by it.

# EVE Isk per Hour (EVE-IPH)

EVE Isk per Hour is a Windows desktop application for [EVE Online](https://www.eveonline.com/) that helps industrialists plan and price manufacturing, invention, reactions, mining, and other production activities. It calculates ISK-per-hour profitability across blueprints, components, and market data using the EVE Static Data Export (SDE) and live data from CCP's ESI API.

This repository is written in VB.NET (Visual Studio, .NET Framework, WinForms) against SQLite via `System.Data.SQLite`.

---

## Requirements

- Windows 10 or later
- [.NET Framework 4.7.2+](https://dotnet.microsoft.com/download/dotnet-framework) (matches [app.config](app.config))
- Visual Studio 2019 or later with the **Visual Basic** workload (only required if building from source)
- A populated `EVEIPH DB.sqlite` database file placed next to the executable (see below)

> **You must supply the SQLite database yourself.** The database is *not* committed to this repository because it is large and is regenerated each time CCP publishes a new SDE.

---

## Getting `EVEIPH DB.sqlite`

If you launch the app without a properly-built database you will see SQLite errors such as:

```
System.Data.SQLite.SQLiteException: 'SQL logic error
no such table: ESI_STATUS_ITEMS'
```

This happens because EVE-IPH expects a SQLite file named **`EVEIPH DB.sqlite`** to live in the application's working directory, and that file must contain both:

- the standard **SDE tables** (`invTypes`, `industryActivity*`, `mapSolarSystems`, etc.), and
- the **EVE-IPH-specific tables** (`ESI_STATUS_ITEMS`, `ESI_ENDPOINT_ROUTE_TO_SCOPE`, `ESI_CHARACTER_DATA`, `ESI_CHARACTER_LOYALTY_POINTS`, `ESI_CHARACTER_PLANETS`, `ESI_CORPORATION_DATA`, `ESI_CORPORATION_DIVISIONS`, `ESI_CORPORATION_ROLES`, …).

> ⚠️ Nothing in the EVE-IPH source code creates the `ESI_*` tables — they live in a pre-baked template DB that the project maintainer publishes. Building the SDE alone is **not** enough.

The expected filename is hard-coded in [Globals.vb](Globals.vb#L57):

```vbnet
Public Const SQLiteDBFileName As String = "EVEIPH DB.sqlite"
```

There are two supported ways to obtain this file.

### Option A — Download the prebuilt database (recommended)

The official prebuilt DB (SDE + ESI tables, ready to use) is published in the [EVEIPH/LatestFiles](https://github.com/EVEIPH/LatestFiles) repo and is what the in-app updater pulls:

```
https://raw.githubusercontent.com/EVEIPH/LatestFiles/master/EVEIPH%20DB.sqlite
```

PowerShell one-liner (run from the folder that contains `EVE Isk per Hour.exe`, e.g. `bin\Debug\`):

```powershell
Invoke-WebRequest `
  -Uri "https://raw.githubusercontent.com/EVEIPH/LatestFiles/master/EVEIPH%20DB.sqlite" `
  -OutFile "EVEIPH DB.sqlite"
```

Then launch the app — the `no such table` error will be gone.

### Option B — Build a fresh SDE and merge it (advanced)

Use this when CCP has shipped a new SDE and the prebuilt DB above is out of date.

1. Get the prebuilt `EVEIPH DB.sqlite` from Option A first — you need its `ESI_*` tables.
2. Clone and run [EVE-SDE-Database-Builder](https://github.com/NolieRavioli/EVE-SDE-Database-Builder).
3. In its UI, set:
   - **Database Type:** SQLite
   - **Database Name:** `EVEIPH DB.sqlite` (the builder appends `.sqlite` itself, so the field can read just `EVEIPH DB`)
   - **SDE Download Folder:** any scratch folder; click **Download** to fetch the latest SDE.
   - **SDE File Folder:** the extracted SDE folder (containing `bsd\`, `fsd\`, `universe\`, …).
   - **Final Database Folder:** any folder — *not* the EVE-IPH folder, so you don't overwrite the prebuilt DB.
   - Click **Check All**, then **Build Database**.
4. Run the **EVEIPH Updater** project (`EVE-IPH-Update-Program\`). It copies the `ESI_*` and other user tables from your existing prebuilt DB into the freshly-built SDE DB and swaps them in.

The updater uses the `OLD_` prefix convention (`OLD_PREFIX` in [frmUpdaterMain.vb](EVE-IPH-Update-Program/frmUpdaterMain.vb#L93)) to identify the previous DB during the merge.

## Building from source

1. Clone the repo.
2. Open [EVE Isk per Hour.sln](EVE%20Isk%20per%20Hour.sln) in Visual Studio.
3. Restore NuGet packages (Newtonsoft.Json, System.Data.SQLite, etc. — already vendored under `packages\`).
4. Build the `EVE Isk per Hour` project.
5. Drop `EVEIPH DB.sqlite` into the build output folder (`bin\Debug\` or `bin\Release\`).
6. Run.

The solution also contains two helper projects:

- **EVE-IPH-Update-Program** — handles patching the database between SDE releases.
- **EVEIPH SQLite DLL Updater** — swaps out the native SQLite interop DLL when needed.

Neither helper is required for normal use of the main app.

---

## ESI / CCP API registration

EVE-IPH uses CCP's ESI for character data (skills, blueprints, assets, industry jobs, standings, market orders, etc.). To use the character-linked features you need to register an application at <https://developers.eveonline.com/> and plug your **Client ID** and **Secret Key** into the in-app ESI settings dialog. The app uses the standard OAuth2 flow with a localhost callback.

Without ESI credentials the manufacturing/pricing features still work — you just can't import your own character.
